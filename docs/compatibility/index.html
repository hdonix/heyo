What the verdicts mean

Launches cleanly
The command showed something of its own (a list with items, a text, a form), or ran to its end, with no error and no failure message — and the static check found nothing in its code that cannot work on Heyo. Only the first screen was looked at; no action was pressed.
Needs configuration
It stops at something only its user can give: a required preference (an API key, a server address), an account, a sign-in in the browser, an AI model. Required preferences were filled with made-up values; what happens with real ones was not tested.
Partly
It launches, but its code holds parts that cannot work here (AppleScript, macOS programs, a missing API) which the launch did not reach; or it showed its content and a failure message besides.
Inconclusive
Nothing that says either way: an empty view, a view still loading or nothing at all when time was up, a failure message of the extension's own, or a program or another application's files that the test machine does not have.
Fails
An error was thrown or the runtime process ended; or it failed for a reason that is Heyo's or the platform's: macOS-only code, a missing API, an error inside the runtime.

An extension “launches cleanly” when all its commands do; “needs configuration” when all its commands either launch cleanly or stop at configuration; “fails” when none gets anywhere; “partly” for every mix in between.

How this was done, and what it cannot tell

Sample: the 100 most-downloaded extensions of the Raycast Store. Ordering: download_count, descending, over the whole public listing (the Store's own order is not by downloads and it takes no sort parameter).

Each command ran in a process of its own with 15 s to settle and 1024 MiB of memory; isolation: bubblewrap (no access to the user's files); network: allowed, and each command launched a second time without.

  1. A launch is not a use. Each command was started once and watched until it went quiet; no action was pressed, no form submitted. An empty list that searches as you type had “test” typed into it, and that is all the typing there was.
  2. The host is a stand-in. Requests to the Heyo host (applications, clipboard, selection, windows, opening things) were answered with small made-up data and nothing was really opened, pasted or changed. What the real host does with them is not tested here.
  3. No real accounts. Required preferences were filled with made-up values, sign-ins were not completed. “Needs configuration” therefore says where the test stopped, not that the extension works once configured.
  4. The test machine is a bare Linux system: none of the applications that extensions drive (browsers, editors, password managers, Homebrew, Docker) is installed, and it has no desktop session. An extension that reads another application's files finds none.
  5. The static check reads text. It finds AppleScript and macOS programs in a command's own code whether or not the launch reaches them; it can miss what is built at run time, and it can flag code that never runs on Linux.
  6. Extensions were run for real, as Node.js programs. With bubblewrap they saw only the system's programs, the runtime and a scratch directory; that is a restriction, not a security boundary anyone should rely on, and with the network allowed they could reach it.
  7. One machine, one day. Services answer differently from one day and one address to the next.
